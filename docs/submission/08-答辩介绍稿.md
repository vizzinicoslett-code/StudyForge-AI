# StudyForge AI 答辩介绍稿

建议按自然语速讲约 2～3 分钟。方括号中的模式说明需要根据真实演示情况选择，不要照读模板标记。

老师好，我们的作品是 StudyForge AI，一个面向大学生的课程学习助手。

做这个项目，是因为复习时我们经常有很多课件和笔记，但看完资料，并不代表已经理解。我们希望 AI 能帮同学把学习过程理顺：先知道资料在讲什么，再建立知识框架，最后通过练习发现自己还没有掌握的部分。

使用方法很简单。上传一份 PDF、文本或 Markdown 资料后，系统提取原文。点击重点提炼，可以看到课程主线、核心知识点和建议的学习优先级。接着生成提纲，内容会标记为理解、记忆、计算或易错。遇到疑问可以提问，回答旁边能展开资料片段，方便核对依据。

然后我们生成一组五题或十题的小测验，只使用单选题和判断题。学生答完后，系统显示分数、正确答案与解析，并根据这次答错的知识点给出复习建议。这样，资料阅读、自我测试和反馈就连接起来了。

AI 在这个产品里主要负责总结、组织、解释和生成内容。我们没有直接相信模型输出，而是要求它返回固定格式的 JSON，再由后端检查字段、题数、选项和答案范围。测验评分由程序完成，所以模型生成和确定性的程序逻辑各自承担适合的任务。

另一个亮点是资料增强。系统把资料切成片段，先找与问题相关的内容，再提供给模型。这体现了简化版 RAG 的思想，不需要复杂的向量数据库，也能说明“先找依据，再生成回答”。它仍然可能检索不准或出现幻觉，所以我们保留原文引用，提醒使用者核对关键知识。

[如果本次使用 Mock：今天展示的是 Mock 演示模式，它根据资料组织规则化内容，用来验证交互流程，没有调用真实大模型。项目已经实现真实 API 接入和协议测试，配置密钥后可以切换。]

[如果本次使用真实 AI：今天使用的是已配置的真实模型服务，界面明确标记模式。我们另外保留了 Mock，方便在课堂网络或额度受限时展示产品操作。]

项目最大的收获，是理解了 AI 应用不是只有一条提示词。资料处理、任务约束、输出检查、交互和反馈都需要配合。小组使用了 Codex 辅助开发，并由成员补充实际验证与展示工作；我们会如实说明每个人的贡献。谢谢老师。
