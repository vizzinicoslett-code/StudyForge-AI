# 当前公开展示版本说明

本课程展示版本使用 Mock / 本地规则处理，不调用在线 AI 服务、不需要 API Key。文中模型接口与 Prompt 部分属于原设计的技术说明；当前录屏和答辩应按 Mock 分支介绍。公开版本不填写真实成员信息，不使用未获公开许可的课件。

# AI 基本原理说明

## 1. 大语言模型是什么

大语言模型是从大量文本中学习语言规律的模型。它根据已给出的上下文预测并生成后续文本，因此可以完成概括、解释和出题等任务。它并不是一个保证每句话正确的知识数据库，也不等于真正拥有人的意识。

本项目真实模式把任务和课程片段发送给配置的模型服务；Mock 则由普通程序摘录和组织资料，不使用大语言模型。区分两者是诚实演示 AI 应用的前提。

## 2. Prompt 是什么

Prompt 就是给模型的任务说明和相关背景。例如“请根据下面的课程资料提炼 5～10 个知识点，并按规定 JSON 格式输出”。本项目用系统提示词描述助手角色，用任务提示词说明本次要做什么，再加入资料与格式要求。

## 3. 为什么 Prompt 会影响结果

同一份资料可以被概括、解释或用于出题。任务说明决定模型关注什么；资料提供依据；输出格式决定结果是否能被程序读取。明确说出范围、数量和格式，通常比只说“帮我学习”更容易得到可用内容。但清楚的提示词不能保证答案永远正确。

## 4. 如何把课程资料提供给 AI

上传的文件先被后端解析为文本。短资料在总结和提纲任务中使用全部切分片段。问答时，程序根据问题选择相关片段，并给每个片段加上 S1、S2 等编号，一起放进模型上下文。模型被要求优先依这些片段回答，并返回来源编号。

较长的资料会抽取分布在不同位置的片段，页面显示可能未覆盖全部内容的提示。更可靠的使用方式是按章节上传。

## 5. 简化版 RAG / Context Augmentation

RAG 可以理解为“先找资料，再让 AI 回答”。本项目的流程是：

```text
课程文本 → 切成小片段 → 问题词片段匹配 → 选择相关资料 → 放入 Prompt → 生成答案
```

切分约 900 字、重叠约 120 字，减少边界处的内容丢失。检索使用中文双字词与英文单词，结合词在各片段出现的情况给相关片段排序。它体现资料增强思想，但没有向量数据库或语义嵌入。换用近义词、模糊指代和复杂问题时，检索可能遗漏相关资料。

## 6. 为什么采用 JSON

普通文章适合阅读，却不容易直接变成答题页面。JSON 用固定字段表示题型、问题、选项、答案和解析，程序就能稳定地渲染选项并计算成绩。模型返回的 JSON 先由后端读取，前端收到的是验证后的结构化结果。

## 7. 为什么需要 Schema Validation

Schema 相当于数据的格式规则：每道单选必须有 4 个选项、判断题必须有 2 个固定选项、答案必须落在有效范围内。校验可以阻止缺字段、错误类型、重复题目和无效答案进入页面。

项目使用 Zod 校验所有 AI 任务的数据，还额外检查题数、选项重复和答案范围。**格式正确不代表知识正确**：Schema 能判断答案写成了 A，却不能证明 A 在学术上一定成立。

## 8. AI 幻觉是什么

模型可能生成听起来合理、实际却错误或没有资料支持的内容，这称为幻觉。例如编造定义、推导或资料来源。即使回答流畅，也不能把流畅当成正确的证据。

## 9. 本项目如何减少幻觉

- 优先提供用户课程资料并要求依据片段作答。
- 要求不编造来源，后端检查来源编号是否来自本次上下文。
- 资料不足或使用补充解释时，显示明确提示。
- 给学生提供可展开原文，重要结论可以直接核对。
- 题目与解析要求可由资料验证，低随机性有助于输出稳定。
- 长资料抽样和 Mock 演示都明示边界。

这些方法能降低风险，不能彻底消除幻觉；来源编号真实也不意味着回答准确理解了该片段。学生与教师仍应核对关键知识，真实模型的质量还需要实际试用和评价。
